# TM Concept 0.1.57

[English](#english) · [Türkçe](#türkçe)

## English

### What changed since 0.1.56

**Which file to download**
- **`TMConcept-win-x64-Setup.exe` — installed edition (recommended on Windows).** Installs for your user only and updates itself.
- **`TMConcept-Portable-win-x64.exe` — portable edition.** One program file, nothing installed.
- **Linux:** `tm-concept-portable-linux-x64.tar.gz` or `tm-concept-portable-linux-arm64.tar.gz`.
- The `.nupkg`, `.AppImage` and `releases.*.json` files are for the installed edition's updates. The installed 0.1.56 updates itself.

**Reinstall from scratch deletes the old components first, then downloads**
- After its confirmation (which shows the folder and its size), **Reinstall from scratch** first deletes the whole components folder for
  good: no recycle bin, no copy set aside, no `tools.old-…` folder next to it. Only then does it download what you had again.
  Until 0.1.56 the old folder was renamed aside while the new one was installed, so the disk held both copies (tens of gigabytes).
- Your database, keys, backups, profiles, concepts and videos are outside that folder and are never touched.

**Updates delete each component's old files first**
- **Update components** (after a new app version, or when a component is installed again) deletes the old files of each component right
  before its own download, then downloads it. The old copy never stays next to the new one.

**An install that was cut short goes on**
- Each install writes its components into a small journal (`install-journal.json` in the data folder) before anything is deleted or
  downloaded; a component leaves it only after its install finished and it was checked.
- If the app was closed, crashed or lost power in the middle, the next start deletes only the half-finished component's files (its
  unfinished `.part` download too) and downloads it again (one confirmation lists the downloads). The finished components stay.

**Old leftovers are removed at start**
- What earlier versions left (`tools.old-*`, `tools.failed-*`, `tools.aside-*`, the `tools.reinstalling` marker, the shared downloads
  folder, `*.unpack` folders) is deleted permanently at start without a question; each one is written to the log.

**For developers**
- Core: `IInstallJournal`, `IComponent.ReplacedPaths`, `IKeepingWipe` / `KeepingWipe`, `ComponentPlanner.ClearUnfinishedAsync`,
  `EngineNeeds`. Desktop: `InstallJournalFile`, `InstallResume` (start-up step `startup.install_resume`), `InstallOutcome.Declined`.
- The rename-aside reinstall (old folder kept, new folder installed beside it, the old one put back on failure) is removed.

## Türkçe

### 0.1.56 sürümünden bu yana değişenler

**Hangi dosyayı indirmeli**
- **`TMConcept-win-x64-Setup.exe` — kurulan tür (Windows'ta önerilen).** Yalnız senin kullanıcın için kurulur ve kendini günceller.
- **`TMConcept-Portable-win-x64.exe` — taşınabilir tür.** Tek program dosyası, hiçbir şey kurulmaz.
- **Linux:** `tm-concept-portable-linux-x64.tar.gz` ya da `tm-concept-portable-linux-arm64.tar.gz`.
- `.nupkg`, `.AppImage` ve `releases.*.json` dosyaları kurulan türün güncellemeleri içindir. Kurulu 0.1.56 kendini günceller.

**Sıfırdan kur önce eski bileşenleri siler, sonra indirir**
- Onaydan sonra (klasörü ve boyutunu gösterir) **Sıfırdan kur** önce bileşen klasörünün tamamını kalıcı siler: geri dönüşüm kutusu yok,
  kenara alınan kopya yok, yanında `tools.old-…` klasörü yok. Sahip olduklarını ancak bundan sonra yeniden indirir.
  0.1.56'ya kadar eski klasör kenara alınıp yenisi yanına kuruluyordu; diskte iki kopya (onlarca GB) kalıyordu.
- Veritabanın, anahtarların, yedeklerin, profillerin, konseptlerin ve videoların o klasörün dışındadır; asla dokunulmaz.

**Güncellemeler her bileşenin eski dosyalarını önce siler**
- **Bileşenleri güncelle** (yeni sürümden sonra ya da bir bileşen yeniden kurulurken) her bileşenin eski dosyalarını kendi indirmesinden
  hemen önce siler, sonra indirir. Eski kopya yenisinin yanında kalmaz.

**Yarıda kalan kurulum devam eder**
- Her kurulum, bir şey silinmeden ya da indirilmeden önce bileşenlerini küçük bir günlüğe (veri klasöründe `install-journal.json`) yazar;
  bileşen ancak kurulumu bitip denetlendikten sonra oradan çıkar.
- Program ortada kapandıysa, çöktüyse ya da elektrik gittiyse sonraki açılış yalnız yarım kalan bileşenin dosyalarını (bitmemiş `.part`
  indirmesi dahil) siler ve onu yeniden indirir (tek onay indirmeleri listeler). Biten bileşenler kalır.

**Eski artıklar açılışta silinir**
- Eski sürümlerin bıraktıkları (`tools.old-*`, `tools.failed-*`, `tools.aside-*`, `tools.reinstalling` işareti, ortak indirme klasörü,
  `*.unpack` klasörleri) açılışta sorusuz kalıcı silinir; her biri günlüğe yazılır.

**Geliştiriciler için**
- Core: `IInstallJournal`, `IComponent.ReplacedPaths`, `IKeepingWipe` / `KeepingWipe`, `ComponentPlanner.ClearUnfinishedAsync`,
  `EngineNeeds`. Desktop: `InstallJournalFile`, `InstallResume` (açılış adımı `startup.install_resume`), `InstallOutcome.Declined`.
- Kenara alarak sıfırdan kurma (eski klasör tutulur, yenisi yanına kurulur, başarısızsa eskisi geri konur) kaldırıldı.
