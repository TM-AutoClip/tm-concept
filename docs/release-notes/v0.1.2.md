# TM Concept 0.1.2

[English](#english) · [Türkçe](#türkçe)

## English

A fix release for the player, for programs left running after closing, and for memory.

### Fixes

**Player**
- The seek bar follows your hand. While you drag it, the position no longer jumps back; the video moves there when you let go.
  Clicking anywhere on the bar jumps there too; a plain click on the handle or a right click does not move the video.
- A video without a thumbnail no longer shows a black area. When you choose it, the thumbnail is made again (the first picture that is
  not black, as in the list) and shown in the list and in the player. If that is not possible (for example ffmpeg is missing), the log
  says why and the page goes on.
- Leaving **Produced videos** pauses the player and frees the memory of its pictures. The video and the position stay.

**Programs started by the app**
- ffmpeg, Node and the browser the engines start now always end with the app. On Windows they end even when the app is closed from the
  Task Manager or crashes. On Linux they are ended when the app closes or stops on an error.
- If the app was killed on Linux, the next start ends what the app left running: only programs whose file is in the app's own tools
  folder and that no running copy of the app owns. Nothing else on your computer is touched, even a program that has a tools path in its
  command line.
- Starting the app a second time for the same data folder now always brings the running window forward. On Linux a start from a
  terminal and one from the menu could open two copies before.
- Closing the window during a render still asks first, stops the render and waits up to 20 seconds. Whatever still runs after that is
  ended.
- Work files of a video that was cut off by closing the app are removed at the next start. A rejected code stays for reading for 7 days,
  and paid scene images stay for a retry.

**Memory**
- On Linux (and the Raspberry Pi) the program inside the tar.gz is no longer compressed a second time. A compressed program is unpacked
  into memory at every start; an uncompressed one is read from the file only as needed. The download stays the same size (the tar.gz
  compresses it); the unpacked program file is larger (about 147 MB instead of 62 MB). The Windows exe stays compressed.
- After a video is made and when the player is closed, the app gives the memory it no longer needs back to the system (about 20 MB less
  after playing a video). The app's own data in memory is small (10–20 MB); most of the rest is the window, the fonts and the picture
  drawing, which these changes do not touch.
- The settings page is built the first time you open it. Thumbnails and the player's poster are no longer decoded larger than they are
  shown.

**Logging**
- Errors that were ignored before are now in the log with their cause: a picture that cannot be loaded, a failure while reading the
  sound of a video, image prompts the model returned in a broken form, ffmpeg's own message when a thumbnail cannot be made. Logs name files, never your folders.
- The first log line of a start shows the exact version and the commit it was built from.

**For maintainers**
- The release scripts refuse to build from uncommitted changes, so the version inside the files always matches the tagged commit
  (in 0.1.1 it did not).

### Memory: before and after

Measured on Windows 11 (x64) with the release exe files and a fresh data folder: one profile, two 30-second 1080×1920 videos. Two runs
each; the table shows the average (runs differ by up to 5 MB, so the idle values are the same). "Private" is memory only this app uses;
"working set" also counts shared system files.

| Moment | 0.1.1 private | 0.1.2 private | 0.1.1 working set | 0.1.2 working set |
|---|---|---|---|---|
| Idle on the first page | 163 MB | 169 MB | 238 MB | 245 MB |
| A video selected | 183 MB | 176 MB | 262 MB | 259 MB |
| Playing (20 s) | 193 MB | 191 MB | 270 MB | 273 MB |
| After playing, on another page | 197 MB | 178 MB | 278 MB | 264 MB |

The same 0.1.2 code built without the inner compression (as the Linux packages now are), measured once on Windows: idle 129 MB private
/ 180 MB working set, a video selected 143 / 202 MB, playing 157 / 215 MB, after playing 146 / 206 MB.

Not yet measured on a Raspberry Pi 5 (0.1.1 used about 230 MB there with the window open).

### Known limits

- Videos up to 3 minutes; no long horizontal videos.
- The files are not code-signed (Windows SmartScreen asks once).
- Revideo is experimental. On Linux ARM64, HyperFrames and Revideo need the system Chromium (Remotion brings its own browser).
- The player shows the picture at up to 720 pixels on its longer side and 30 frames per second.
- On Linux, the player's sound needs PulseAudio or PipeWire (package `libpulse0`); without it, videos play silently. The Linux sound path
  and the Linux process clean-up have not yet been tried on a real Linux desktop.
- On Linux, a system Chromium started by an engine is not ended by the start-up clean-up (it is not in the app's tools folder); it
  normally ends when its Node process ends.
- No real request to any AI provider was made during development tests (they use fake HTTP).

## Türkçe

Oynatıcı, kapatınca açık kalan programlar ve bellek için bir düzeltme sürümü.

### Düzeltmeler

**Oynatıcı**
- Sarma çubuğu elini takip ediyor. Sürüklerken konum artık geri zıplamıyor; bırakınca video oraya gidiyor. Çubuğun herhangi bir yerine
  tıklamak da oraya atlıyor; düğmeye düz tıklamak ya da sağ tık konumu değiştirmiyor.
- Küçük resmi olmayan video artık siyah alan göstermiyor. Seçince küçük resim yeniden yapılıyor (listedeki gibi siyah olmayan ilk kare)
  ve listede ve oynatıcıda görünüyor. Yapılamazsa (ör. ffmpeg yoksa) günlük nedenini yazıyor, sayfa çalışmaya devam ediyor.
- **Üretilen Videolar**'dan çıkınca oynatıcı duraklıyor ve resimlerinin belleğini bırakıyor. Video ve konum kalıyor.

**Programın başlattığı programlar**
- ffmpeg, Node ve motorların açtığı tarayıcı artık her zaman programla birlikte kapanıyor. Windows'ta program Görev Yöneticisi'nden
  kapatılsa ya da çökse bile kapanıyorlar. Linux'ta program kapanınca ya da bir hatayla durunca kapatılıyorlar.
- Linux'ta program zorla kapatıldıysa sonraki açılış, programın açık bıraktıklarını kapatıyor: yalnız dosyası programın kendi araçlar
  klasöründe olan ve çalışan hiçbir program kopyasına ait olmayanlar. Bilgisayardaki başka hiçbir şeye dokunulmuyor, komut satırında
  araçlar yolu geçen bir programa bile.
- Aynı veri klasörü için program ikinci kez başlatılınca artık her zaman açık olan pencere öne geliyor. Linux'ta terminalden ve menüden
  açılan iki kopya önceden ikisi de açılabiliyordu.
- Render sürerken pencereyi kapatmak yine önce soruyor, render'ı durduruyor ve 20 saniyeye kadar bekliyor. Ondan sonra hâlâ çalışan
  ne varsa kapatılıyor.
- Program kapanınca yarıda kalan videonun iş dosyaları sonraki açılışta siliniyor. Reddedilen kod okumak için 7 gün kalıyor, ücreti
  ödenmiş sahne görselleri yeniden deneme için duruyor.

**Bellek**
- Linux'ta (ve Raspberry Pi'de) tar.gz içindeki program artık ikinci kez sıkıştırılmıyor. Sıkıştırılmış program her açılışta belleğe
  açılır; sıkıştırılmamış olan dosyadan yalnız gerektikçe okunur. İndirme boyutu aynı kalıyor (tar.gz onu sıkıştırıyor); açılmış program
  dosyası daha büyük (62 MB yerine yaklaşık 147 MB). Windows exe'si sıkıştırılmış kalıyor.
- Bir video üretildikten sonra ve oynatıcı kapanınca program artık gerekmeyen belleği sisteme geri veriyor (video oynattıktan sonra
  yaklaşık 20 MB daha az). Programın bellekteki kendi verisi küçük (10–20 MB); geri kalanın çoğu pencere, yazı tipleri ve görüntü
  çizimi, bu değişiklikler onlara dokunmuyor.
- Ayarlar sayfası ilk açıldığında kuruluyor. Küçük resimler ve oynatıcının kapak resmi gösterildiğinden büyük açılmıyor.

**Günlük**
- Önceden yok sayılan hatalar artık nedeniyle günlükte: yüklenemeyen bir resim, bir videonun sesi okunurken çıkan hata, modelin bozuk
  biçimde döndürdüğü görsel istemleri, küçük resim yapılamadığında ffmpeg'in kendi mesajı. Günlük dosya adlarını yazar, klasörlerini asla.
- Açılıştaki ilk günlük satırı tam sürümü ve derlendiği commit'i gösteriyor.

**Geliştiriciler için**
- Yayın betikleri commit edilmemiş değişiklikle derlemeyi reddediyor; böylece dosyaların içindeki sürüm her zaman etiketlenen commit'le
  aynı (0.1.1'de değildi).

### Bilinen kısıtlar

- Videolar en çok 3 dakika; uzun yatay video yok.
- Dosyalar kod imzalı değil (Windows SmartScreen bir kez sorar).
- Revideo deneysel. Linux ARM64'te HyperFrames ve Revideo sistem Chromium'unu ister (Remotion kendi tarayıcısını getirir).
- Oynatıcı görüntüyü uzun kenarda en çok 720 piksel ve saniyede 30 kareyle gösterir.
- Linux'ta oynatıcının sesi PulseAudio ya da PipeWire ister (`libpulse0` paketi); yoksa videolar sessiz oynar. Linux ses yolu ve Linux
  süreç temizliği henüz gerçek bir Linux masaüstünde denenmedi.
- Linux'ta bir motorun açtığı sistem Chromium'u açılış temizliğinde kapatılmaz (programın araçlar klasöründe değil); normalde Node
  süreci bitince o da biter.
- Geliştirme testlerinde hiçbir yapay zekâ sağlayıcısına gerçek istek atılmadı (sahte HTTP).
