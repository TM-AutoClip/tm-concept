# TM Concept 0.1.39

[English](#english) · [Türkçe](#türkçe)

## English

### What changed since 0.1.38

**Which file to download**
- **`TMConcept-win-x64-Setup.exe` — installed edition (recommended on Windows).** Installs for your user only and updates itself.
- **`TMConcept-Portable-win-x64.exe` — portable edition.** One program file, nothing installed.
- **Linux:** `tm-concept-portable-linux-x64.tar.gz` or `tm-concept-portable-linux-arm64.tar.gz`.
- The `.nupkg`, `.AppImage` and `releases.*.json` files are for the installed edition's updates. The installed 0.1.38 updates itself.

**The database no longer works on the window's thread**
- **Every read and write runs in the background.** Before, the database library did its work on the thread that asked for it, so a
  page that read the database could hold the window for a moment. Now every read and write runs off the window's thread; the window
  only waits for the answer.
- **Faster page changes.** Opening the encrypted database used to cost the same each time (the key was prepared again for every piece of
  work). Opened connections are now kept and used again, so switching pages and profiles opens the database much faster.
- **No more "database is locked" between two saves.** Saves to the database now take turns (one at a time) while reading goes on side by
  side, so two saves at the same moment (for example a concept batch and the run's update) no longer stop each other.
- **Safe with backups and the vault.** Before a backup is restored, the database is set aside or upgraded, the vault is locked or the
  master password is changed, the kept connections are closed and the app checks that the file is free.
- Nothing is cached in memory: every change is written at once, as before.

**For developers**
- New `DatabaseWork` (`Storage/Database`): the thread-pool run, the one-writer gate per file and `ReleaseFiles` (closes the pool and checks
  the file is no longer held). `ConceptDatabase.ReadAsync` / `WriteAsync`; every store goes through them. Connection pooling is on
  (`Pooling=true`); the file format and the key settings did not change. `DatabaseWorkTests`. No database change, no schema step.

## Türkçe

### 0.1.38 sürümünden bu yana değişenler

**Hangi dosyayı indirmeli**
- **`TMConcept-win-x64-Setup.exe` — kurulan tür (Windows'ta önerilen).** Yalnız senin kullanıcın için kurulur ve kendini günceller.
- **`TMConcept-Portable-win-x64.exe` — taşınabilir tür.** Tek program dosyası, hiçbir şey kurulmaz.
- **Linux:** `tm-concept-portable-linux-x64.tar.gz` ya da `tm-concept-portable-linux-arm64.tar.gz`.
- `.nupkg`, `.AppImage` ve `releases.*.json` dosyaları kurulan türün güncellemeleri içindir. Kurulu 0.1.38 kendini günceller.

**Veritabanı artık pencerenin iş parçacığında çalışmıyor**
- **Her okuma ve yazma arka planda.** Önceden veritabanı kitaplığı işini onu isteyen iş parçacığında yapıyordu; veritabanını okuyan bir
  sayfa pencereyi bir an tutabiliyordu. Artık her okuma ve yazma pencerenin iş parçacığı dışında çalışıyor; pencere yalnız cevabı bekliyor.
- **Daha hızlı sayfa geçişleri.** Şifreli veritabanını açmak her seferinde aynı süreyi alıyordu (anahtar her iş için yeniden
  hazırlanıyordu). Açılan bağlantılar artık saklanıp yeniden kullanılıyor; sayfa ve profil geçişlerinde veritabanı çok daha hızlı açılıyor.
- **İki kayıt arasında "database is locked" yok.** Veritabanına kayıtlar artık sırayla (birer birer) yapılıyor, okumalar yan yana
  sürüyor; aynı anda gelen iki kayıt (ör. bir konsept grubu ve çalışmanın güncellemesi) birbirini durdurmuyor.
- **Yedek ve kasayla güvenli.** Yedekten geri yüklemeden, veritabanı kenara alınmadan ya da yükseltilmeden, kasa kilitlenmeden ya da ana
  parola değiştirilmeden önce saklanan bağlantılar kapatılıyor ve program dosyanın serbest olduğunu denetliyor.
- Bellekte önbellek yok: her değişiklik eskisi gibi hemen yazılıyor.

**Geliştiriciler için**
- Yeni `DatabaseWork` (`Storage/Database`): iş parçacığı havuzunda çalıştırma, dosya başına tek yazar kapısı ve `ReleaseFiles` (havuzu
  kapatır, dosyanın tutulmadığını denetler). `ConceptDatabase.ReadAsync` / `WriteAsync`; bütün depolar bunlardan geçiyor. Bağlantı havuzu
  açık (`Pooling=true`); dosya biçimi ve anahtar ayarları değişmedi. `DatabaseWorkTests`. Veritabanı değişmedi, göç adımı yok.
