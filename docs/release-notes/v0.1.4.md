# TM Concept 0.1.4

[English](#english) · [Türkçe](#türkçe)

## English

Logs you can read, and a way to report a problem. Nothing is sent anywhere by itself: you prepare a zip, look at it, and attach it to a
GitHub issue yourself.

### What changed since 0.1.3

**Logs**
- One plain text file per day and per process, in the data folder's `logs` folder: `app-2026-11-06.log` for the window, and
  `speech-worker-2026-11-06.log` for the local voice process (0.1.3 wrote everything into `tmconcept-20261106.log`). The date is the local
  date; a new file starts at midnight while the app runs.
- Every start and every new file begins with one line naming the app, version and commit, process kind, operating system, architecture,
  .NET version and process id.
- Levels: Information, Warning, Error and Critical. Debug is not written.
- Kept for 7 days, by the date in the file name (not by when the file was last written): checked at every start and at every day change.
  The 0.1.0–0.1.3 `tmconcept-….log` files follow the same rule. Any other file in the folder is left alone.
- At most 20 MB per file and day; after that one warning line is written and nothing more until the next day.
- Before a line is written, the library folder becomes `<library>` and the two folder names under it (named after the profile and the
  concept title) become `<profile>` and `<folder>`; a data or documents folder outside your home folder (portable `--data-dir`, a
  redirected Documents folder, a network share) becomes `<data>` / `<documents>`; your home folder becomes `~`; e-mail addresses become
  `<e-mail>`; Bearer / Basic tokens and API keys (OpenAI, Anthropic, OpenRouter, DeepSeek, Google, fal, Z.ai, GitHub, AWS, Slack, JSON
  web tokens) are masked. A child program's output is cut only after the paths in it are masked.
- Profile names and concept / video titles stay out of the log file: the activity panel shows them, the log line has `<name>` /
  `<title>` in their place. Opening a folder or a file is logged as "a folder" / "a .mp4 file", without its name. Concept and narration
  texts are not logged.
- Two processes of the same kind (a second start, a second voice process) take a shared lock to write at the end of the file, so neither
  overwrites lines of the other. When a new day's file cannot be opened at first, its header and the 7-day sweep come with the first
  entry that opens it.
- Now in the log: every provider request with its provider, operation, HTTP status and duration (never the body or the key); each
  child program (Node, npm, Chrome, ffmpeg, tar) with its exit code and duration; the start and end of every video, concept run, tool
  install and engine sample, with their duration; settings changes by name (language, drawing, notifications, step models, price
  overrides, API key saved / deleted / tested — the provider name only, never the key); a missing model or key for a step; the
  voice process's own start, model load time and each scene's length and time.
- Crashes are Critical, each written once: an unhandled exception, an unobserved task exception, an exception that reached the interface
  thread, and the automatic unlock failing (the keyring could not open the database).
- fal image status checks (one a second while an image waits) are one line per image with the wait and the number of checks, not one
  line per check. Saving the step models logs only the steps that changed, after they are saved.
- Linux: `gio trash` and `secret-tool` calls are logged with their command, exit code and duration; a failed `gio trash` is a warning
  before the XDG trash folder is used; a key that `secret-tool` could not remove from the keyring after a protection change is a warning
  (it was silently ignored).
- When Node, npm, Chrome, ffmpeg or tar fails, the error message shows the first lines that look like an error (at most 500
  characters), not the last 400 characters of everything.

**Report a problem**
- **Report a problem** at the bottom of the left menu opens a small window that says that nothing is sent automatically and what the zip
  holds.
- **Prepare logs** writes `tm-concept-logs-<date>-<time>.zip` into the data folder's `reports` folder and shows it in the file manager.
  It holds the log files of the last 7 days (masked once more) and `system.txt`: version and commit, operating system, architecture, .NET,
  interface language, drawing mode, portable or default data folder, which tools and engines are installed. While the app is unlocked,
  every profile name and concept or video title in the database becomes `<name>` in the zip (this also covers older log files and
  exception messages). Never the database, API keys, concept or narration texts, or video files. The logs do name the settings you
  changed and their new values (interface language, drawing mode, notifications, each step's model and effort, price overrides). The
  window and the README say to open the zip and read it before sharing it publicly. The last 5 zips are kept.
- **Report on GitHub** opens the issue form of `TM-AutoClip/tm-concept` in your browser with the version, operating system and
  architecture filled in; describe what happened and drag the zip into the form. If the browser cannot be opened, the address is copied.
- **Copy details** copies the `system.txt` text.
- The repository has an issue form (`.github/ISSUE_TEMPLATE/bug_report.yml`); the README has a "Reporting a problem" section.

### Memory and processor when idle

Same conditions as for 0.1.3: the release file (Windows 11 x64), a fresh data folder (`--data-dir`, so the first-start window is
open), measured 90 seconds after start without touching anything; processor time is the share of all cores between second 30 and 90.
Five runs each (three in a row, then two alternating 0.1.3 / 0.1.4); the table shows the middle value and the range.

| Build | Private working set (Task Manager "Memory") | Private bytes | Working set | Threads | Processor (30–90 s) |
|---|---|---|---|---|---|
| 0.1.3 | 34.7 MB (32.7–35.5) | 37.7 MB (35.6–38.2) | 93.6 MB | 10 | 0 % |
| 0.1.4 | 35.3 MB (34.9–36.1) | 38.0 MB (37.7–38.9) | 95.4 MB | 10 | 0 % |

The difference (+0.6 MB in the middle) is inside the spread between runs of the same file. The log file stays open between entries (no
reopen per line); nothing runs while the app is idle: no timer, no extra thread. The report window and the zip code are loaded only
when they are used.

## Türkçe

Okunabilir günlükler ve hata bildirme yolu. Hiçbir şey kendiliğinden bir yere gönderilmez: bir zip hazırlarsın, içine bakarsın ve GitHub'daki
hata kaydına kendin eklersin.

### 0.1.3'ten bu yana değişenler

**Günlükler**
- Gün başına ve süreç başına bir düz metin dosyası, veri klasörünün `logs` klasöründe: pencere için `app-2026-11-06.log`, yerel ses süreci
  için `speech-worker-2026-11-06.log` (0.1.3 her şeyi `tmconcept-20261106.log` dosyasına yazıyordu). Tarih yerel tarihtir; program açıkken
  gece yarısı yeni dosya başlar.
- Her açılış ve her yeni dosya; programı, sürümü ve commit'i, süreç türünü, işletim sistemini, mimariyi, .NET sürümünü ve süreç
  numarasını yazan bir satırla başlar.
- Seviyeler: Information, Warning, Error ve Critical. Debug yazılmaz.
- 7 gün saklanır; dosya adındaki tarihe göre (son yazılma zamanına göre değil): her açılışta ve her gün değişiminde bakılır. 0.1.0–0.1.3'ün
  `tmconcept-….log` dosyaları da aynı kurala uyar. Klasördeki başka dosyalara dokunulmaz.
- Dosya ve gün başına en çok 20 MB; sonra bir uyarı satırı yazılır ve ertesi güne kadar başka bir şey yazılmaz.
- Bir satır yazılmadan önce kitaplık klasörü `<library>` olur ve altındaki iki klasör adı (profil ve konsept başlığından gelir)
  `<profile>` ve `<folder>` olur; ev klasörünün dışındaki bir veri ya da belgeler klasörü (taşınabilir `--data-dir`, yeri değiştirilmiş
  Belgeler klasörü, ağ paylaşımı) `<data>` / `<documents>` olur; ev klasörün `~` olur; e-posta adresleri `<e-mail>` olur; Bearer / Basic
  belirteçleri ve API anahtarları (OpenAI, Anthropic, OpenRouter, DeepSeek, Google, fal, Z.ai, GitHub, AWS, Slack, JSON web token)
  gizlenir. Bir alt programın çıktısı, içindeki yollar gizlendikten sonra kısaltılır.
- Profil adları ve konsept / video başlıkları günlük dosyasına girmez: işlem günlüğü paneli onları gösterir, günlük satırında yerlerinde
  `<name>` / `<title>` vardır. Bir klasörün ya da dosyanın açılması adı olmadan, "a folder" / "a .mp4 file" olarak yazılır. Konsept ve
  anlatım metinleri günlüğe yazılmaz.
- Aynı türden iki süreç (ikinci açılış, ikinci ses süreci) dosyanın sonuna yazmak için ortak bir kilit alır; biri diğerinin satırlarının
  üstüne yazmaz. Yeni günün dosyası ilk seferde açılamazsa başlık satırı ve 7 günlük temizlik, dosyayı açan ilk kayıtla gelir.
- Artık günlükte: her sağlayıcı isteği sağlayıcı, işlem, HTTP durumu ve süresiyle (gövde ya da anahtar asla); her alt program (Node, npm,
  Chrome, ffmpeg, tar) çıkış kodu ve süresiyle; her videonun, konsept üretiminin, araç kurulumunun ve motor örneğinin başlangıcı ve bitişi
  süreleriyle; ayar değişiklikleri adlarıyla (dil, çizim, bildirimler, adım modelleri, fiyat düzeltmeleri, API anahtarı kaydedildi /
  silindi / denendi — yalnız sağlayıcı adı, anahtar asla); bir adımın modeli ya da anahtarı eksikse; ses sürecinin kendi açılışı, model
  yükleme süresi ve her sahnenin uzunluğu ve süresi.
- Çökmeler Critical ve her biri bir kez yazılır: yakalanmamış bir hata, gözlenmemiş bir görev hatası, arayüz iş parçacığına ulaşan bir
  hata ve otomatik kilit açmanın başarısız olması (anahtarlık veritabanını açamadı).
- fal görsel durum yoklamaları (görsel beklerken saniyede bir) her yoklama için değil, görsel başına bir satırdır: bekleme süresi ve
  yoklama sayısıyla. Adım modelleri kaydedilince yalnız değişen adımlar, kaydedildikten sonra yazılır.
- Linux: `gio trash` ve `secret-tool` çağrıları komutu, çıkış kodu ve süresiyle yazılır; başarısız bir `gio trash`, XDG çöp klasörü
  kullanılmadan önce bir uyarıdır; koruma değişikliğinden sonra `secret-tool`'un anahtarlıktan silemediği eski anahtar bir uyarıdır
  (önceden sessizce geçiliyordu).
- Node, npm, Chrome, ffmpeg ya da tar başarısız olunca hata mesajı, her şeyin son 400 karakteri yerine hataya benzeyen ilk satırları
  gösterir (en çok 500 karakter).

**Hata bildir**
- Sol menünün altındaki **Hata bildir**, hiçbir şeyin kendiliğinden gönderilmediğini ve zip'te ne olduğunu söyleyen küçük bir pencere açar.
- **Günlükleri hazırla**, veri klasörünün `reports` klasörüne `tm-concept-logs-<tarih>-<saat>.zip` yazar ve dosya yöneticisinde gösterir.
  İçinde son 7 günün günlük dosyaları (bir kez daha gizlenmiş olarak) ve `system.txt` vardır: sürüm ve commit, işletim sistemi, mimari,
  .NET, arayüz dili, çizim kipi, taşınabilir ya da varsayılan veri klasörü, hangi araçların ve motorların kurulu olduğu. Program kilidi
  açıkken veritabanındaki her profil adı ile konsept ve video başlığı zip'te `<name>` olur (eski günlük dosyaları ve hata mesajları da
  dahil). Veritabanı, API anahtarları, konsept ve anlatım metinleri ya da video dosyaları asla içinde değildir. Günlükler değiştirdiğin
  ayarları ve yeni değerlerini yazar (arayüz dili, çizim kipi, bildirimler, her adımın modeli ve çaba düzeyi, fiyat düzeltmeleri). Pencere
  ve README, herkese açık paylaşmadan önce zip'i açıp okumayı söyler. Son 5 zip saklanır.
- **GitHub'da bildir**, `TM-AutoClip/tm-concept` hata formunu tarayıcında sürüm, işletim sistemi ve mimari dolu olarak açar; ne olduğunu
  yaz ve zip'i forma sürükle. Tarayıcı açılamazsa adres panoya kopyalanır.
- **Bilgileri kopyala**, `system.txt` metnini panoya kopyalar.
- Depoda bir hata formu var (`.github/ISSUE_TEMPLATE/bug_report.yml`); README'de "Hata bildirme" bölümü var.

### Boştayken bellek ve işlemci
