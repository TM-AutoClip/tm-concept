# TM Concept 0.1.3

[English](#english) · [Türkçe](#türkçe)

## English

A smaller, lighter release. The app only talks to online models, so it should not weigh like a video editor. 0.1.3 removes what was
heavy without being needed all the time.

### What changed

**Size**
- The program file is about a third of 0.1.2: Windows exe 23.3 MiB (58.6 MiB before), the Linux program inside the tar.gz 23.1 MiB on x64
  and 22.2 MiB on ARM64 (133.4 / 146.8 MiB before). The downloads are 16.4 / 15.8 MiB (52.8 / 53.3 MiB before).
- The program is trimmed: only the parts of .NET and the libraries the app really uses are inside.
- The database code no longer uses Entity Framework Core; it reads and writes the same file directly through Microsoft.Data.Sqlite. Your
  data file is unchanged: 0.1.0–0.1.2 files open as they are.

**Voice**
- The voice libraries (sherpa-onnx with ONNX Runtime, 21–37 MiB depending on the system) are no longer inside the program. They are a tool
  like Node and ffmpeg: Settings → **Tools** shows **sherpa-onnx** with its size (about 8–13 MB), downloaded from the official sherpa-onnx
  2.0.1 GitHub release, pinned and checked with SHA-256. Installing **Supertonic 3** installs them too, with one confirmation that names both
  downloads.
- The voice now speaks in a separate process (the app starts itself again as a "speech worker"). The window never loads the voice
  libraries; the worker holds the voice model only while scenes are spoken and ends 60 seconds after the last one, so its memory goes back to
  the system (in 0.1.2 the model stayed loaded in the app until it closed). If the voice fails badly, the window stays open.
- Without a ready voice the video is still made silent, with the yellow warning in the log.
- If the voice fails, the log has the voice process's own reason. Cancelling a video while a scene is spoken ends the voice process at
  once (it does not finish the scene first).
- If you used the voice in 0.1.2: the model is still installed; only the libraries are missing. Press Install next to Supertonic 3 (or
  sherpa-onnx) once; only the libraries are downloaded, not the model again.

**Memory**
- The window is drawn by the processor by default. It looks the same; the graphics driver no longer sits in the app's process (on Windows
  that was about 68 MB and 48 threads; on a Raspberry Pi, Mesa with LLVM). If scrolling or the player feels slow on your computer, turn on
  Settings → **General** → **Draw the window with the graphics card** and restart.
- Each start's log says how the window is drawn ("Drawing with the processor" or "Drawing with the graphics card"), a few lines after
  the version line.

### Memory: before and after

Same conditions for every number: the release file, a fresh data folder (`--data-dir`, so the first-start window is open), measured 90
seconds after start without touching anything. Windows 11 x64: two runs each, the table shows the average (runs differ by up to 5 MB).
Raspberry Pi 5 (8 GB, Raspberry Pi OS, ARM64): three samples 10 s apart, all equal. "Private" is memory only this app uses.

**Windows**

| Build | Private bytes | Private working set (Task Manager "Memory") | Working set | Threads |
|---|---|---|---|---|
| 0.1.2 | 133.0 MB | 76.9 MB | 187.9 MB | 58 |
| 0.1.3 | **34.3 MB** | **31.3 MB** | **90.5 MB** | 10 |
| 0.1.3 with "Draw the window with the graphics card" on | 104.4 MB | 48.6 MB | 135.2 MB | 58 |
| 0.1.3 without compression inside the file (one run) | 34.2 MB | 24.0 MB | 82.0 MB | 10 |

**Raspberry Pi 5**

| Build | RSS | PSS | Private | RssAnon | RssFile | RssShmem |
|---|---|---|---|---|---|---|
| 0.1.2 | 197 MB | 132 MB | 115 MB | 51 MB | 123 MB | 22 MB |
| 0.1.3 | **100 MB** | **84 MB** | **83 MB** | 30 MB | 31 MB | 38 MB |
| 0.1.3 with the graphics card on | 170 MB | 112 MB | 102 MB | 49 MB | 83 MB | 37 MB |
| 0.1.3 without compression inside the file | 99 MB | 83 MB | 81 MB | 30 MB | 44 MB | 24 MB |

The "graphics card" rows were measured with the trimmed build just before the default changed (the drawing code is the same); the
"without compression" rows with a build of `4987716`, which differs from the release only on the Tools page.

Where the rest goes (Pi, 0.1.3, from `/proc/<pid>/smaps`): about 25 MB is the code the .NET JIT compiles at start, about 22 MB the program
file's pages in use (the .NET runtime and the libraries), about 18 MB native memory (Skia, fonts, X11), about 10 MB other anonymous memory (where the
garbage-collected heap lives). The app's own objects are small: 3 MB on the heap after a collection (Windows heap dump).

Speaking with the local voice (Pi, two short lines in Turkish and English, the model loaded once): 23 s the first time (files not yet in
the disk cache), 7 s the second time; the worker process peaked at 281–286 MB RSS and ended afterwards.

**Compression inside the single file** was measured again after the shrinking: on the Pi the compressed and the uncompressed file use the
same memory (±2 MB); on Windows the uncompressed file has about 7 MB less private working set but is nearly twice as large. All files are
compressed (0.1.2 left the Linux program uncompressed).

### Not in this release

- **Native AOT** (compiling the app ahead of time). The code is ready for it: every project now runs the trim and AOT analyzers and a
  Windows AOT build compiles without a warning. A test Windows AOT build used 90.2 MB private bytes / 32.7 MB private working set /
  92.6 MB working set with the graphics card on (one run; the trimmed build with the graphics card: 104.4 / 48.6 / 135.2 MB), and its exe is
  27.2 MiB plus 20.3 MiB of native libraries next to it (AOT cannot put them inside the exe). It is not released because the Linux files
  cannot be built this way on Windows: Native AOT for Linux has to be compiled on Linux (x64 and ARM64) with clang, and the release scripts
  build every system on one machine. On the Pi AOT would remove most of the 25 MB of JIT code.
- **Invariant globalization** (no ICU) is not turned on: the duplicate check folds Turkish text with the tr-TR culture (İ/ı), which needs
  ICU, and on the Pi ICU costs only about 1 MB of PSS.

### Known limits

- Videos up to 3 minutes; no long horizontal videos.
- The files are not code-signed (Windows SmartScreen asks once).
- Revideo is experimental. On Linux ARM64, HyperFrames and Revideo need the system Chromium (Remotion brings its own browser).
- The player shows the picture at up to 720 pixels on its longer side and 30 frames per second. Drawing on the processor was measured idle;
  the player's smoothness on slow computers has not yet been tried by a person.
- On Linux, the player's sound needs PulseAudio or PipeWire (package `libpulse0`); without it, videos play silently.
- No real request to any AI provider was made during development tests (they use fake HTTP). The local voice was run for real (Windows and
  Raspberry Pi 5).

## Türkçe

Daha küçük ve daha hafif bir sürüm. Program yalnız çevrimiçi modellerle konuşuyor; bir video düzenleyici kadar yer tutmamalı. 0.1.3, her
zaman gerekmediği hâlde ağır olanları çıkarıyor.

### Değişenler

**Boyut**
- Program dosyası 0.1.2'nin yaklaşık üçte biri: Windows exe 23,3 MiB (önce 58,6 MiB), tar.gz içindeki Linux programı x64'te 23,1 MiB,
  ARM64'te 22,2 MiB (önce 133,4 / 146,8 MiB). İndirmeler 16,4 / 15,8 MiB (önce 52,8 / 53,3 MiB).
- Program budanmış (trimmed) olarak yayımlanıyor: içinde yalnız .NET'in ve kitaplıkların gerçekten kullanılan parçaları var.
- Veritabanı kodu artık Entity Framework Core kullanmıyor; aynı dosyayı Microsoft.Data.Sqlite ile doğrudan okuyup yazıyor. Veri dosyan
  değişmedi: 0.1.0–0.1.2 dosyaları olduğu gibi açılıyor.

**Ses**
- Ses kitaplıkları (ONNX Runtime ile sherpa-onnx, sisteme göre 21–37 MiB) artık programın içinde değil. Node ve ffmpeg gibi bir araç oldular:
  Ayarlar → **Araçlar**'da boyutuyla (yaklaşık 8–13 MB) **sherpa-onnx** satırı var; resmî sherpa-onnx 2.0.1 GitHub sürümünden indirilir,
  sabitlenmiş SHA-256 ile denetlenir. **Supertonic 3**'ü kurmak onları da kurar; tek onay penceresi iki indirmeyi de yazar.
- Ses artık ayrı bir süreçte konuşuyor (program kendini "ses işçisi" olarak yeniden başlatıyor). Pencere ses kitaplıklarını hiç yüklemiyor;
  işçi ses modelini yalnız sahneler okunurken tutuyor ve sonuncusundan 60 saniye sonra kapanıyor, belleği sisteme dönüyor (0.1.2'de model
  program kapanana kadar yüklü kalıyordu). Ses ağır bir hatayla çökse de pencere açık kalıyor.
- Ses hazır değilse video yine sessiz üretiliyor, günlükte sarı uyarıyla.
- Ses başarısız olursa günlükte ses sürecinin kendi gerekçesi yazıyor. Bir sahne okunurken videoyu iptal etmek ses sürecini hemen
  kapatıyor (önce sahneyi bitirmiyor).
- 0.1.2'de sesi kullandıysan: model hâlâ kurulu, yalnız kitaplıklar eksik. Supertonic 3'ün (ya da sherpa-onnx'in) yanındaki Kur'a bir kez bas;
  model yeniden inmez, yalnız kitaplıklar iner.

**Bellek**
- Pencereyi varsayılan olarak işlemci çiziyor. Görünüm aynı; ekran kartı sürücüsü artık programın sürecinde durmuyor (Windows'ta bu yaklaşık
  68 MB ve 48 iş parçacığıydı; Raspberry Pi'de LLVM ile Mesa). Bilgisayarında kaydırma ya da oynatıcı yavaş gelirse Ayarlar → **Genel** →
  **Pencereyi ekran kartıyla çiz** seçeneğini aç ve programı yeniden başlat.
- Her açılışın günlüğü, sürüm satırından birkaç satır sonra pencerenin nasıl çizildiğini yazıyor ("Drawing with the processor" ya da
  "Drawing with the graphics card").

### Bu sürümde olmayanlar

- **Native AOT** (programı önceden derlemek). Kod buna hazır: artık her proje budama ve AOT çözümleyicileriyle derleniyor ve Windows AOT
  derlemesi tek uyarı vermeden derleniyor. Bir deneme Windows AOT derlemesi ekran kartı açıkken 90,2 MB özel bayt / 32,7 MB özel çalışma
  kümesi / 92,6 MB çalışma kümesi kullandı (tek ölçüm; ekran kartı açık budanmış derleme: 104,4 / 48,6 / 135,2 MB); exe'si 27,2 MiB, yanında
  20,3 MiB yerel kitaplık (AOT onları exe'nin içine koyamıyor). Yayımlanmadı, çünkü Linux dosyaları Windows'ta bu yolla derlenemiyor:
  Linux için Native AOT, Linux'ta (x64 ve ARM64) clang ile derlenmeli; yayın betikleri ise her sistemi tek makinede derliyor. Pi'de AOT,
  25 MB'lık JIT kodunun çoğunu kaldırırdı.
- **Değişmez kültür (invariant globalization, ICU'suz)** açılmadı: tekrar denetimi Türkçe metni tr-TR kültürüyle katlıyor (İ/ı), bunun için
  ICU gerekiyor; Pi'de ICU yalnız yaklaşık 1 MB PSS tutuyor.

### Bilinen kısıtlar

- Videolar en çok 3 dakika; uzun yatay video yok.
- Dosyalar kod imzalı değil (Windows SmartScreen bir kez sorar).
- Revideo deneysel. Linux ARM64'te HyperFrames ve Revideo sistem Chromium'unu ister (Remotion kendi tarayıcısını getirir).
- Oynatıcı görüntüyü uzun kenarda en çok 720 piksel ve saniyede 30 kareyle gösterir. İşlemciyle çizim boştayken ölçüldü; oynatıcının yavaş
  bilgisayarlardaki akıcılığını henüz bir insan denemedi.
- Linux'ta oynatıcının sesi PulseAudio ya da PipeWire ister (`libpulse0` paketi); yoksa videolar sessiz oynar.
- Geliştirme testlerinde hiçbir yapay zekâ sağlayıcısına gerçek istek atılmadı (sahte HTTP). Yerel ses gerçekten çalıştırıldı (Windows ve
  Raspberry Pi 5).
