## English

### What changed since 0.1.6

**Storage goes through EF Core again**
- The database is read and written through EF Core (as in 0.1.0–0.1.2) instead of hand-written SQL; it is still encrypted with
  SQLite3 Multiple Ciphers.
- **No backward compatibility:** 0.1.7 opens only databases and backups of its own schema version (kept in the database's settings).
  Files of 0.1.0–0.1.6 are not upgraded any more. When the database does not open for this reason, the unlock window says so and offers
  **Set aside and start fresh**: the database and its key file are renamed in the data folder (`.set-aside-<time>`), never deleted, and
  the app starts empty as at the first start. Restoring accepts only backups made by this version (a format 02 backup of 0.1.1–0.1.5 or
  a backup of 0.1.6 is refused with that reason, not as a wrong password).

**Deleting for good no longer makes the file smaller (no VACUUM)**
- 0.1.6 ran `VACUUM` after a permanent delete and on every backup copy. VACUUM is an SQL statement with no EF Core counterpart, so 0.1.7
  does not run it.
- What is deleted is still unreadable: the SQLite build overwrites deleted rows **and the pages they free** with zeros (secure delete; the
  app checks it every time a database comes in and refuses a build without it). Tests look for deleted text in the raw file — after a
  permanent delete and in a backup copy without the parts that were not chosen — and find none.
- What changes: the database file and backups do not shrink after a delete. The zeroed pages stay in the file (and in a backup's
  database copy) until SQLite reuses them for new data, so a backup can be larger than the same content made by 0.1.6. Whether this is
  acceptable is an **open decision**; until it is made, it is the behaviour of this version.

**Long answers stream; the video code has room for its thinking**
- Video code answers were cut off at 32 000 output tokens: the model's adaptive thinking takes from the same budget (two Opus 5.5 answers,
  effort high, stopped after about 5 minutes and about 0.65 $ each). The budget is now 64 000 tokens, or the model's own limit when that
  is smaller, for the code and for its single repair. The estimate's high end counts this whole budget (it counted 14 000 before).
- Answers are read while they stream: Anthropic always (it already asked for a stream, but the app waited for the whole body under one
  15-minute limit), the OpenAI-compatible providers for the long calls (concepts, video code; with `stream_options.include_usage`, sent
  once more without it when a provider rejects it). A streamed answer must start within 15 minutes; then it may run up to 60 minutes and
  stops only when nothing arrives for 3 minutes. The log line of a streamed call has its time, size, first-line time and request id; a
  stream that breaks carries the tokens already billed into the cost.
- A cut-off video code says what happened: "the video code was cut off because it was too long; spent X $" (it said "the complete
  concepts before the cut were kept", which is the concept page's text).

**Fixes in video making and the estimates**
- A narration model that could not be prepared (not installed, wrong language) stopped the queue with an error after the warning; the
  video is made silent now, as the warning says.
- "Sample images" chosen for a profile that has none made a video without images and said nothing; now it says so (activity line and a
  note in the video's details).
- The concept estimate with the meaning check left out the earlier concepts it embeds first (up to 300 per batch of 20 the first time,
  or after the model changed). They are in the estimate now, and the page says how many; with the local model it costs nothing but takes a
  while.
- The details of a video whose narration skipped words showed a text key instead of the note.

**What a failed video paid, and clearer cost details**
- A video that fails keeps what it paid until then: the queue row says "spent because of the failure: X $" (added up over the failed
  tries of that item, also after a restart), and the month's spending has a "failed videos" part (it used to leave this money out).
- The cost details of a made video follow the work: the concept's share of its generation run (the run's cost ÷ the concepts it kept,
  for example 0.11 $ for 5 concepts → 0.022 $), the narration text and scene split (on this computer, free), the image prompts (they
  showed as `step.image-prompt`), the images, the narration voice, the video code (its repair included), then the total. Lines of one
  step are added up. The concept share is not in the video's own total shown in the list (that run is already counted with the concept
  runs); the details' total says it includes it.

**A made video keeps what a re-render needs**
- Each video is a version folder inside its concept's folder: `<profile>/<date>-<number>-<title>/v1/` with `video.mp4`, `thumbnail.jpg`,
  `subtitles.srt`, `narration.txt`, plus `source/` (the engine project as it rendered: the app's files, the model's code, `input.json`
  with the timing, the scene images) and `audio/` (the narration clip of each scene). The new versions (a new voice with the same code, new
  code for another engine) start from them.
- The narration text is always written; the "Narration text as a file" choice is gone.
- Deleting a video with its files moves the concept's folder to the recycle bin when the version is the only thing in it.

**The window is drawn with the graphics card by default**
- Settings → Drawing → "Draw the window with the graphics card" is on in a new install (0.1.3–0.1.6 drew on the processor by default).
  A setting saved earlier is kept; turning it off still saves about 50–70 MB of memory.

**No activity panel at the bottom**
- The "Activity log" strip at the bottom of the window is gone. Every line it showed is still written, complete, to the log file
  (Report a problem → Prepare logs).
- What mattered from it stays on the screen: a failed video's notification says why and what it spent (the queue row says it too), a
  finished video's notification has its cost and its problems (silent, no images, skipped words), a failed concept run or a skipped
  meaning check is on the concepts page, the cost of describing an image on the profile page, a component that could not be removed and
  the sample render on the settings page, a failed daily backup and an error on the interface thread as a notification.

**Installs run in a window over the app**
- When the app downloads and installs something a choice needs (ffmpeg, Node.js, an engine's packages and browser, a voice, an image
  model, the meaning-check model), a modal window lists every component in install order: waiting, downloading (with its own progress and
  what it is fetching), installed, failed with the reason, or skipped because something it needs failed. The app cannot be used meanwhile;
  Cancel stops after the running download.
- When everything is installed the window closes by itself and the work that waited (a video, a concept run, a sample to listen to)
  goes on. After a failure the window stays with the reason until you close it; nothing is started or paid for.

**The video page's models fit without scrolling**
- "Models and settings" no longer scrolls inside a 420 px box: the three steps (video code with its engine, images, narration) are compact
  cards side by side. A step's purpose is its title's tooltip, and a long note shows three lines (the whole note is its tooltip). The area
  still folds.
- The estimate, the price table date and "Subtitles in the picture" stand above the queue they are about; the queue scrolls when it is
  long.

**Markers in the channel concept and the extra request**
- An "Insert a marker…" drop-down under the profile's channel concept and the concept page's extra request puts a marker at the cursor
  (replacing a selection): `[hook opening]`, `[hard cut]`, `[soft transition]`, `[pause]`, `[emphasis]`, `[map]`, `[timeline]`,
  `[comparison]`, `[big number]`, `[ending question]`, `[short sentences]` (in Turkish `[sert geçiş]`, `[vurgu]`…; both spellings are
  understood).
- The concept prompt explains only the markers the texts use, with their meaning, after the extra request (so the cached part does not
  change): for example "[hard cut] = scenes change with hard cuts; say so in the scene lines". The model applies them and never copies a
  marker into the concept; the video code then draws what the scene lines say.

**Concept page: focus drop-downs, "Suggest topics", clearer duplicate checks**
- Focus drop-downs under the extra request, defined as data (`Concepts/Files/focus.json`): a category (General, History, Technology;
  a profile made from a template starts with its own) with its drop-downs — History: period, region, subject; Technology: era, field,
  angle — and the general ones every category shows: tone (mysterious, educational, dramatic…), audience, structure. What is chosen goes
  into the prompt as a FOCUS line in the video's language, after the extra request; the estimate counts it.
- **Suggest topics** asks a cheap chat model (the new optional "Topic suggestions" step on the page, chosen like the other steps;
  recommended Claude Haiku 5.5, GLM-5.3 Flash, DeepSeek Flash) for about ten topics for the channel, category, focus and extra request,
  not repeating earlier titles, in the interface language. The cost of one press is shown before; the cost after; a click adds a topic
  to the extra request. The call is a run of its own, so the month's spending counts it.
- The two duplicate checks were easy to take for one: "Duplicate check by words" (the check box; free, compares the words of titles
  and summaries, no model) and "Duplicate check by meaning" (the optional model step; local free or online). They are different checks
  that can run together; the labels and notes say so now (the meaning step's "off" note claimed the word check runs even when its box
  was unticked).

**Produced videos: a narrow list, wide details with the whole texts**
- The list is a narrow column (300 px, smaller thumbnails) and the details take the rest of the width (they were 420 px).
- The details have tabs: **Narration, scene by scene** — every scene's length, what is on screen and its whole narration, from the
  version folder's `source/input.json` (the texts and timing the video was rendered with); **Concept text** — title, summary and the
  whole script from the database (open by default now, it was a closed expander); **Details and cost** as before. When the concept was
  deleted the narration is still shown (it comes from the files); a folder without `source/input.json` says so.

**Versions of a produced video: a new voice without AI cost, new code for another engine**
- The details show the video's versions (v1, v2…; one row per video in the list, its newest version). Choose one to watch it, read its
  texts or delete it; the others stay.
- **New version → new voice:** every scene's narration can be edited and extended in its own box, with a drop-down of narration markers
  that this computer applies: `[pause 0.5 s]`, `[pause 1 s]`, `[pause 2 s]` (silence), `[slow]`, `[fast]`, `[normal speed]` (the voice's
  speed for what follows). Choose a voice (or off for a silent version). The voice is made again here, each scene lasts as long as its
  new clip (pauses included), `input.json` gets the new timing and texts, and the SAME kept code is rendered again — no model call. The
  subtitles follow the new text. A local voice costs nothing; an online voice's cost is shown and confirmed first. The edited text with
  its markers is kept with the version (`narration-edit.json`), so the next edit starts from it.
- **New version → another engine:** the code is written for one engine, so HyperFrames ↔ Remotion ↔ Revideo needs new code from the
  video code model (the card's model and engine). The estimate is shown and confirmed first; the scene images, the voice clips and the
  texts are used again; the usual one repair applies. What it paid is in the version's cost (and kept as a failed video's cost when it
  fails).
- Visual markers (transitions, emphasis on screen) are not offered in the narration editor: they need new code. Bracket text that is
  no narration marker is not spoken.
- Every version is a folder of its own next to the others (`v2/`, `v3/`…) with the same files as the first; nothing of an unfinished
  version is left behind. The models are made ready like any process (keys, licenses, the install window) and saved for the profile.

**Videos in twelve languages; your notes stay in yours**
- The profile's **video language** (it was "content language", Turkish or English) is one of Turkish, English, German, Spanish, French,
  Italian, Portuguese, Dutch, Polish, Russian, Swedish and Indonesian: languages the local voice Supertonic 3 speaks, written in a script
  the subtitle font draws, with words separated by spaces. Japanese, Chinese, Korean, Arabic and Hindi are left out for now.
- The channel concept, the extra request, the focus and the sample image captions may be written in the interface language (or any
  other): the concept prompt (Turkish for Turkish videos, English for every other one) says that the « » texts may be in another
  language, and that the title, summary, narration and on-screen lines are written only in the video language, with names, terms and
  dates as its speakers write them. A series part is named in the video language ("— Teil 3"). The video code model is told the video
  language too, for any word it writes into the code itself.
- Estimates use the video language's own rates: words per second of narration (German 2.2, Spanish 2.6, Russian 2.1…; Turkish 2.3 and
  English 2.6 as before), characters per word and per token. A language the app does not know gets the English rates.
- The word duplicate check leaves out the filler words of the video language (with the English ones) and knows the part words of every
  language ("Teil 3", "Parte 2", "Часть 4"); "parte" inside a name ("Bonaparte 3") is no longer a part number.
- Subtitles end a sentence also before a closing quote or bracket ("halten.“") and at "…"; a word longer than a line is split over
  lines instead of being cut off.
- Sample image descriptions are written in the interface language (they are notes for you).

**A pronunciation dictionary for each video language**
- Before a voice speaks, the narration goes through the dictionary of the video language: a whole word is replaced by how it should be
  read ("Viking" → "Vikink" in Turkish, where Supertonic read it the English way). Only the voice gets the changed text; subtitles,
  `input.json` and `narration.txt` keep the written word. The speech cache is keyed on the spoken text, so a changed word is spoken anew.
- Whole words only ("Viking'ler" and "(Viking)" match, "Vikingler" does not — add that form too if needed); upper and lower case follow
  the language's own rules one letter at a time (Turkish "VİKİNG" matches "Viking", "VIKING" does not), and the narration word's case is
  kept ("VİKİNG" → "VİKİNK"). The longest entry wins ("New York" before "New").
- Turkish comes with a small list (46 foreign names Turkish texts keep in their own spelling: Viking, Google, Shakespeare, Einstein,
  New York…). **Settings → Voice and pronunciation** lists a language's words (built in / yours), adds a word with its reading and removes
  yours; your word of the same spelling replaces a built-in one, removing it brings the built-in one back. The words are in the encrypted
  database (schema 5) and go into a backup with the settings.

## Türkçe

### 0.1.6'dan bu yana değişenler

**Depolama yeniden EF Core üzerinden**
- Veritabanı elle yazılmış SQL yerine yeniden EF Core ile okunup yazılıyor (0.1.0–0.1.2'deki gibi); şifreleme yine SQLite3 Multiple
  Ciphers.
- **Geçmişe uyum yok:** 0.1.7 yalnız kendi şema sürümündeki (veritabanının ayarlarında tutulur) veritabanlarını ve yedekleri açar.
  0.1.0–0.1.6 dosyaları artık yükseltilmiyor. Veritabanı bu yüzden açılmazsa kilit penceresi bunu açıkça söyler ve **Kenara al ve
  yeniden başla** önerir: veritabanı ve anahtar dosyası veri klasöründe yeniden adlandırılır (`.set-aside-<zaman>`), asla silinmez, program
  ilk açılıştaki gibi boş başlar. Geri yükleme yalnız bu sürümün yaptığı yedekleri kabul eder (0.1.1–0.1.5'in 02 biçimli yedeği ya da
  0.1.6 yedeği yanlış parola diye değil, bu nedenle reddedilir).

**Kalıcı silme dosyayı artık küçültmüyor (VACUUM yok)**
- 0.1.6 kalıcı silmeden sonra ve her yedek kopyasında `VACUUM` çalıştırıyordu. VACUUM bir SQL komutu, EF Core'da karşılığı yok; 0.1.7
  onu çalıştırmıyor.
- Silinen yine okunamaz: SQLite derlemesi silinen satırları **ve boşalttıkları sayfaları** sıfırlarla eziyor (güvenli silme; program
  her veritabanı girişinde bunu denetliyor, kapalı bir derlemeyi kullanmıyor). Testler silinen metni ham dosyada arıyor — kalıcı
  silmeden sonra ve seçilmeyenleri çıkarılmış yedek kopyasında — ve bulmuyor.
- Değişen: veritabanı dosyası ve yedekler silmeden sonra küçülmüyor. Sıfırlanmış sayfalar SQLite onları yeni veriye kullanana kadar
  dosyada (ve yedeğin veritabanı kopyasında) duruyor; bu yüzden bir yedek, aynı içeriğin 0.1.6'daki yedeğinden büyük olabilir. Bunun
  kabul edilip edilmeyeceği **açık bir karar**; verilene kadar bu sürümün davranışı bu.

**Uzun yanıtlar akışla okunuyor; video kodunun düşünmeye yeri var**
- Video kodu yanıtları 32 000 çıktı jetonunda kesiliyordu: modelin uyarlanabilir düşünmesi aynı bütçeden yiyor (iki Opus 5.5 yanıtı,
  çaba yüksek, yaklaşık 5 dakika ve her biri yaklaşık 0,65 $ sonra durdu). Bütçe artık 64 000 jeton (modelin kendi sınırı daha küçükse o),
  kod için de tek onarımı için de. Tahminin üst ucu bu bütçenin tamamını sayıyor (önce 14 000 sayıyordu).
- Yanıtlar gelirken okunuyor: Anthropic her zaman (zaten akış istiyordu ama program gövdenin tamamını tek bir 15 dakikalık sınırla
  bekliyordu), OpenAI uyumlu sağlayıcılar uzun çağrılarda (konsept, video kodu; `stream_options.include_usage` ile, sağlayıcı reddederse
  onsuz bir kez daha). Akışlı yanıt 15 dakika içinde başlamalı; sonra 60 dakikaya kadar sürebilir, yalnız 3 dakika hiçbir şey gelmezse
  durur. Akışlı çağrının günlük satırında süre, boyut, ilk satır süresi ve istek kimliği var; kopan akışta o ana kadar faturalanan jetonlar
  maliyete girer.
- Kesilen video kodu ne olduğunu söylüyor: "video kodu çok uzun olduğu için yarıda kesildi; harcanan X $" (önce konsept sayfasının metni
  olan "kesilmeden önceki tam konseptler saklandı" çıkıyordu).

**Video üretimi ve tahminlerde düzeltmeler**
- Hazırlanamayan bir seslendirme modeli (kurulu değil, dil uymuyor) uyarıdan sonra kuyruğu hatayla durduruyordu; artık video, uyarının
  dediği gibi sessiz üretiliyor.
- Örnek görseli olmayan bir profilde "Örnek görseller" seçiliyken video görselsiz yapılıyor ve hiçbir şey söylenmiyordu; artık söyleniyor
  (etkinlik satırı ve videonun ayrıntılarında not).
- Anlamca tekrar denetimli konsept tahmini, denetimin önce işlediği eski konseptleri saymıyordu (ilk seferde ya da model değişince 20'lik
  her turda en çok 300). Artık tahmine giriyorlar ve sayfa kaç tane olduğunu söylüyor; yerel modelde ücretsiz ama biraz sürer.
- Seslendirmesi kelime atlayan bir videonun ayrıntılarında not yerine metin anahtarı görünüyordu.

**Başarısız videonun harcadığı ve daha anlaşılır maliyet dökümü**
- Başarısız olan video o ana kadar ödediğini tutuyor: kuyruk satırında "hata nedeniyle harcanan X $" yazıyor (o öğenin başarısız
  denemeleri toplanır, program yeniden açılınca da görünür) ve aylık harcamada "başarısız videolar" kalemi var (önce bu para sayılmıyordu).
- Üretilen videonun maliyet dökümü işin sırasını izliyor: konseptin üretildiği partideki payı (partinin maliyeti ÷ partide kalan konsept
  sayısı; örneğin 5 konsept 0,11 $ → 0,022 $), seslendirme metni ve sahnelere bölme (bu bilgisayarda, ücretsiz), görsel istemleri (önce
  `step.image-prompt` diye görünüyordu), görseller, seslendirme sesi, video kodu (onarımı dahil), sonra toplam. Aynı adımın satırları
  toplanır. Konsept payı listede görünen video tutarına girmez (o parti konsept üretimlerinde zaten sayılıyor); dökümdeki toplam payı
  dahil ettiğini söyler.

**Üretilen video yeniden render için gerekenleri saklıyor**
- Her video, konseptin klasöründe bir sürüm klasörü: `<profil>/<tarih>-<numara>-<başlık>/v1/` içinde `video.mp4`, `thumbnail.jpg`,
  `subtitles.srt`, `narration.txt`; ayrıca `source/` (render edildiği hâliyle motor projesi: programın dosyaları, modelin kodu, zamanlamalı
  `input.json`, sahne görselleri) ve `audio/` (her sahnenin seslendirme klibi). Yeni sürümler (aynı kodla yeni ses, başka motor için yeni
  kod) bunlardan başlar.
- Seslendirme metni her zaman yazılıyor; "Konuşma metnini dosya olarak yaz" seçeneği kalktı.
- Bir video dosyalarıyla silinince, sürüm klasörü konseptin klasöründe tek başınaysa konseptin klasörü geri dönüşüm kutusuna gider.

**Pencere varsayılan olarak ekran kartıyla çiziliyor**
- Ayarlar → Çizim → "Pencereyi ekran kartıyla çiz" yeni kurulumda açık (0.1.3–0.1.6 varsayılan olarak işlemciyle çiziyordu). Önceden
  kaydedilmiş seçim korunur; kapatmak yine yaklaşık 50–70 MB bellek kazandırır.

**Alttaki işlem günlüğü paneli kalktı**
- Pencerenin altındaki "İşlem günlüğü" şeridi yok. Gösterdiği her satır eksiksiz olarak günlük dosyasına yazılmaya devam ediyor (Sorun
  bildir → Günlükleri hazırla).
- Ondaki önemli bilgiler ekranda kalıyor: başarısız videonun bildirimi nedenini ve harcananı söylüyor (kuyruk satırı da), biten videonun
  bildiriminde ücreti ve sorunları (sessiz, görselsiz, atlanan kelimeler) var; başarısız konsept üretimi ya da atlanan anlamca denetim
  konsept sayfasında, görsel açıklamanın ücreti profil sayfasında, kaldırılamayan bileşen ve örnek render ayarlar sayfasında, başarısız
  günlük yedek ve arayüzde yakalanan hata bildirim olarak.

**Kurulumlar programın üstünde bir pencerede**
- Program bir seçimin ihtiyacı olan bir şeyi indirip kurarken (ffmpeg, Node.js, bir motorun paketleri ve tarayıcısı, bir ses, bir görsel
  modeli, anlamca denetim modeli) kalıcı (modal) bir pencere her bileşeni kurulum sırasıyla gösterir: sırada, iniyor (kendi ilerlemesi ve
  ne indirdiğiyle), kuruldu, nedeniyle başarısız, ya da ihtiyaç duyduğu bir şey kurulamadığı için atlandı. Bu sırada program
  kullanılamaz; İptal süren indirmeden sonra durdurur.
- Her şey kurulunca pencere kendiliğinden kapanır ve bekleyen iş (video, konsept üretimi, dinlenecek örnek) devam eder. Hata olursa pencere
  nedeniyle açık kalır, sen kapatırsın; hiçbir şey başlatılmaz, ödenmez.

**Video sayfasındaki modeller kaydırmadan sığıyor**
- "Modeller ve ayarlar" artık 420 piksellik bir kutuda kaymıyor: üç adım (motoruyla video kodu, görseller, seslendirme) yan yana sıkışık
  kartlar. Adımın amacı başlığın ipucunda, uzun not üç satır görünüyor (tamamı ipucunda). Alan yine açılıp kapanıyor.
- Tahmin, fiyat tablosu tarihi ve "Ekranda altyazı" ilgili oldukları kuyruğun üstünde; kuyruk uzayınca kayıyor.

**Kanal konseptinde ve ek istemde işaretler**
- Profildeki kanal konseptinin ve konsept sayfasındaki ek istemin altındaki "İşaret ekle…" açılır listesi seçilen işareti imlecin olduğu
  yere koyar (seçili metin varsa onun yerine): `[merak uyandıran giriş]`, `[sert geçiş]`, `[yumuşak geçiş]`, `[duraklama]`, `[vurgu]`,
  `[harita]`, `[zaman çizelgesi]`, `[karşılaştırma]`, `[büyük sayı]`, `[sonda soru]`, `[kısa cümleler]` (İngilizce `[hard cut]`,
  `[emphasis]`…; iki yazım da anlaşılır).
- Konsept istemi yalnız metinlerde geçen işaretleri anlamlarıyla, ek istemden sonra açıklar (önbelleğe giren kısım değişmez): örneğin
  "[sert geçiş] = sahneler sert kesmeyle değişsin; sahne satırında bunu söyle". Model bunları uygular, işareti konsepte kopyalamaz; video
  kodu sonra sahne satırlarının söylediğini çizer.

**Konsept sayfası: odak listeleri, "Konu öner", daha anlaşılır tekrar denetimleri**
- Ek istemin altında veri olarak tanımlı odak açılır listeleri (`Concepts/Files/focus.json`): bir kategori (Genel, Tarih, Teknoloji;
  şablondan yapılmış profil kendi kategorisiyle başlar) ve onun listeleri — Tarih: dönem, bölge, konu; Teknoloji: dönem, alan, bakış
  açısı — ile her kategoride görünen genel listeler: ton (gizemli, eğitici, dramatik…), izleyici, anlatım biçimi. Seçilenler isteme ek
  istemden sonra, videonun dilinde bir ODAK satırı olarak girer; tahmin bunu sayar.
- **Konu öner** ucuz bir sohbet modelinden (sayfadaki yeni, isteğe bağlı "Konu önerisi" adımı, diğer adımlar gibi seçilir; önerilen
  Claude Haiku 5.5, GLM-5.3 Flash, DeepSeek Flash) kanal, kategori, odak ve ek isteme uygun, eski başlıkları tekrarlamayan yaklaşık on
  konu ister (arayüz dilinde). Bir basışın ücreti önceden, gerçek ücret sonradan görünür; tıklanan konu ek isteme eklenir. Çağrı ayrı bir
  çalıştırma olarak saklanır, aylık harcamaya girer.
- İki tekrar denetimi tek sanılabiliyordu: "Kelimeyle tekrar denetimi" (onay kutusu; ücretsiz, başlık ve özetin kelimelerini karşılaştırır,
  model yok) ve "Anlamca tekrar denetimi" (isteğe bağlı model adımı; yerel ücretsiz ya da online). Bunlar birlikte de çalışabilen farklı
  denetimler; etiketler ve notlar artık bunu söylüyor (anlamca adımın "kapalı" notu, kutusu işaretsizken bile kelime denetiminin
  çalıştığını söylüyordu).

**Üretilen videolar: dar liste, tam metinli geniş ayrıntı**
- Liste dar bir sütun (300 piksel, daha küçük küçük resimler), ayrıntı kalan genişliğin tamamını kullanıyor (420 pikseldi).
- Ayrıntıda sekmeler var: **Seslendirme, sahne sahne** — her sahnenin süresi, ekranda ne olduğu ve seslendirmesinin tamamı; sürüm
  klasöründeki `source/input.json`'dan (videonun render edildiği metinler ve zamanlama); **Konsept metni** — veritabanından başlık, özet ve
  metnin tamamı (artık doğrudan görünüyor, kapalı bir açılır bölümdeydi); **Ayrıntılar ve ücret** eskisi gibi. Konsept silinmişse
  seslendirme yine görünür (dosyalardan gelir); `source/input.json` olmayan klasör bunu söyler.

**Üretilen videonun sürümleri: yapay zekâ masrafsız yeni ses, başka motor için yeni kod**
- Ayrıntıda videonun sürümleri görünüyor (v1, v2…; listede her video tek satır, en yeni sürümüyle). Birini seçip izle, metinlerini oku ya
  da sil; diğerleri kalır.
- **Yeni sürüm → yeni ses:** her sahnenin seslendirme metni kendi kutusunda düzenlenip uzatılabilir; bu bilgisayarın uygulayabildiği
  işaretlerin açılır listesiyle: `[duraklama 0,5 sn]`, `[duraklama 1 sn]`, `[duraklama 2 sn]` (sessizlik), `[yavaş]`, `[hızlı]`,
  `[normal hız]` (sonrasının ses hızı). Bir ses seç (ya da kapalı: sessiz sürüm). Ses burada yeniden üretilir, her sahne yeni klibi
  (duraklamalar dahil) kadar sürer, `input.json` yeni zamanlama ve metinleri alır ve AYNI saklanmış kod yeniden render edilir — model
  çağrısı yok. Altyazı yeni metni izler. Yerel ses ücretsiz; online sesin ücreti önce gösterilip onaylatılır. İşaretli düzenlenmiş metin
  sürümle saklanır (`narration-edit.json`), bir sonraki düzenleme ondan başlar.
- **Yeni sürüm → başka motor:** kod motora özgü olduğundan HyperFrames ↔ Remotion ↔ Revideo için video kodu modeli (karttaki model ve
  motor) yeni kod yazar. Tahmin önce gösterilip onaylatılır; sahne görselleri, ses klipleri ve metinler yeniden kullanılır; olağan tek
  onarım geçerli. Ödenen, sürümün maliyetinde (başarısız olursa başarısız video harcaması olarak saklanır).
- Görsel işaretler (geçişler, ekranda vurgu) seslendirme düzenleyicisinde sunulmuyor: yeni kod gerektirirler. İşaret olmayan köşeli
  parantez metni seslendirilmez.
- Her sürüm diğerlerinin yanında kendi klasörü (`v2/`, `v3/`…), ilkinin dosyalarıyla; yarım kalan sürümden geride bir şey kalmaz.
  Modeller her iş gibi hazırlanır (anahtar, lisans, kurulum penceresi) ve profil için saklanır.

**On iki dilde video; notların senin dilinde kalır**
- Profilin **video dili** (eski adı "içerik dili", Türkçe ya da İngilizce) artık Türkçe, İngilizce, Almanca, İspanyolca, Fransızca,
  İtalyanca, Portekizce, Felemenkçe, Lehçe, Rusça, İsveççe ve Endonezce'den biri: yerel ses Supertonic 3'ün konuştuğu, altyazı yazı
  tipinin çizdiği ve kelimeleri boşlukla ayrılan diller. Japonca, Çince, Korece, Arapça ve Hintçe şimdilik yok.
- Kanal konsepti, ek istek, odak ve örnek görsel açıklamaları arayüz dilinde (ya da başka bir dilde) yazılabilir: konsept istemi (Türkçe
  videoda Türkçe, diğerlerinde İngilizce) « » içindeki metinlerin başka dilde olabileceğini; başlığın, özetin, seslendirmenin ve ekran
  satırlarının yalnız video dilinde, adlar, terimler ve tarihler o dilin konuşanlarının yazdığı gibi yazılacağını söyler. Dizi bölümü video
  dilinde adlandırılır ("— Teil 3"). Video kodu modeline de video dili söylenir (kodun içine kendisi yazdığı kelimeler için).
- Tahminler video dilinin kendi oranlarını kullanır: seslendirmede saniyede kelime (Almanca 2,2, İspanyolca 2,6, Rusça 2,1…; Türkçe 2,3 ve
  İngilizce 2,6 eskisi gibi), kelime ve token başına karakter. Programın tanımadığı bir dil İngilizce oranlarını alır.
- Kelime tekrar denetimi video dilinin dolgu kelimelerini (İngilizceleriyle birlikte) saymaz ve her dilin bölüm kelimesini tanır
  ("Teil 3", "Parte 2", "Часть 4"); bir adın içindeki "parte" ("Bonaparte 3") artık bölüm numarası sayılmaz.
- Altyazı, kapanan tırnak ya da parantezden önceki noktada ("halten.“") ve "…"da da cümleyi bitirir; satırdan uzun bir kelime kesilmez,
  satırlara bölünür.
- Örnek görsel açıklamaları arayüz dilinde yazılır (senin için notlardır).

**Her video dili için telaffuz sözlüğü**
- Ses konuşmadan önce seslendirme metni video dilinin sözlüğünden geçer: bütün bir kelime okunması gerektiği gibi yazılır (Türkçede
  "Viking" → "Vikink"; Supertonic onu İngilizce okuyordu). Değişen metni yalnız ses alır; altyazı, `input.json` ve `narration.txt`
  kelimenin yazıldığı hâlini korur. Ses önbelleği okunan metne göre tutulur, değişen bir kelime yeniden seslendirilir.
- Yalnız bütün kelime eşleşir ("Viking'ler" ve "(Viking)" evet, "Vikingler" hayır — gerekirse o biçimi de ekle); büyük/küçük harf dilin
  kendi kurallarıyla harf harf karşılaştırılır (Türkçede "VİKİNG", "Viking"le eşleşir, "VIKING" eşleşmez) ve metindeki kelimenin harf
  biçimi korunur ("VİKİNG" → "VİKİNK"). En uzun kayıt kazanır ("New York", "New"den önce).
- Türkçe küçük bir hazır listeyle gelir (Türkçe metinlerin kendi yazımıyla bıraktığı 46 yabancı ad: Viking, Google, Shakespeare, Einstein,
  New York…). **Ayarlar → Ses ve telaffuz** bir dilin kelimelerini (hazır / senin) listeler, okunuşuyla kelime ekler ve seninkileri
  siler; aynı yazımlı kendi kelimen hazır olanın yerine geçer, sildiğinde hazır okunuş geri gelir. Kelimeler şifreli veritabanında (şema
  5) durur ve yedeğe ayarlarla birlikte girer.
