# TM Concept 0.1.26

[English](#english) · [Türkçe](#türkçe)

## English

### What changed since 0.1.25

**Which file to download**
- **`TMConcept-win-x64-Setup.exe` — installed edition (recommended on Windows).** Installs for your user only, without administrator
  rights, adds Start menu and desktop shortcuts, appears in Windows' *Apps* (uninstall there) and updates itself.
- **`TMConcept-Portable-win-x64.exe` — portable edition.** One program file, nothing installed; it replaces itself when it updates.
- **Linux:** `tm-concept-portable-linux-x64.tar.gz` or `tm-concept-portable-linux-arm64.tar.gz` (portable, as before).
- The `.nupkg`, `.AppImage` and `releases.*.json` files are for the installed edition's updates; you do not download them yourself.

**Two editions, the same app and the same data**
- Both editions have the same features and use the same data folder (`%LOCALAPPDATA%\TM Concept`): models, keys, settings and projects
  one of them installed are there for the other. The installed program lives in a separate folder (`%LOCALAPPDATA%\TMConcept`), so
  uninstalling it never deletes your data.
- Only one copy runs at a time, whichever edition: a second start brings the open window to the front.
- The installed edition updates through Velopack from this project's GitHub releases. Each package must have the same SHA-256 in the
  release notes as in the package list (and GitHub's digest), or it is not installed; the update is applied only after TM Concept
  closed. From the next version on, a small *delta* package with only what changed is downloaded (0.1.25 had no package to start from).
- The portable files carry no version in their names any more, so a copy that updated itself keeps a true name.
- If another copy or edition already upgraded the database to a newer version, this copy does not touch it and offers **Update this
  copy** on the unlock window.

**Coming from 0.1.25 or older**
- Your app updates itself as usual and gets the **portable** edition, under the old file name (for example `TMConcept-0.1.25-win-x64.exe`
  then runs 0.1.26). The next update renames it to `TMConcept-Portable-win-x64.exe`.
- At its first start it asks once **"Install TM Concept?"**: *Install* downloads this version's Setup from the same release, checks its
  SHA-256, runs it and closes the portable copy (you can delete that file afterwards). *Keep using it portable* is remembered; Settings →
  General → *Edition* still has **Install TM Concept** later. Nothing has to be set up again: both editions share the data.
- Settings → General → *Edition* shows which edition runs and its version, with **Recreate shortcuts** for the installed one.

**Models without an app update**
- New models (online providers the app already knows, local image models for sd-cpp, Ollama text models) can now come from a catalog
  file in this project's repository, read at most once a day in the background, so a release that only adds models needs no app update.
  It is strict: only from this repository over HTTPS, every file at a fixed Hugging Face commit with its SHA-256 and size, Ollama models
  with their exact tag and manifest digest, only engines and options the app already has. A broken file is ignored with one log line and
  never delays the start; the built-in catalog always stays. The file is empty for now.
- An image model folder installed by a newer version is shown on its own in Storage and never taken by "Clean up unused".

**Not yet tried on a real computer:** installing with Setup, the installed edition's updates (the first one comes with 0.1.27), the
update from 0.1.25 to the portable edition and the "Install TM Concept?" handoff were checked by the automated tests only. The Linux
AppImage is built but was not tried on Linux, so it is not offered yet.

## Türkçe

### 0.1.25 sürümünden bu yana değişenler

**Hangi dosyayı indirmeli**
- **`TMConcept-win-x64-Setup.exe` — kurulu tür (Windows'ta önerilir).** Yalnız senin kullanıcına, yönetici izni istemeden kurulur;
  Başlat menüsüne ve masaüstüne kısayol koyar, Windows'un *Uygulamalar* listesinde görünür (oradan kaldırılır) ve kendini günceller.
- **`TMConcept-Portable-win-x64.exe` — taşınabilir tür.** Tek program dosyası, hiçbir şey kurulmaz; güncellenince kendini yeniler.
- **Linux:** `tm-concept-portable-linux-x64.tar.gz` ya da `tm-concept-portable-linux-arm64.tar.gz` (eskisi gibi taşınabilir).
- `.nupkg`, `.AppImage` ve `releases.*.json` dosyaları kurulu türün güncellemeleri için; bunları sen indirmiyorsun.

**İki tür, aynı program, aynı veri**
- İki türün özellikleri aynı ve ikisi de aynı veri klasörünü kullanıyor (`%LOCALAPPDATA%\TM Concept`): birinin indirdiği modeller,
  anahtarlar, ayarlar ve projeler ötekinde de var. Kurulu program ayrı bir klasörde (`%LOCALAPPDATA%\TMConcept`) duruyor; kaldırınca
  verilerin asla silinmiyor.
- Hangi tür olursa olsun aynı anda tek kopya çalışıyor: ikinci kez açınca açık pencere öne geliyor.
- Kurulu tür bu projenin GitHub sürümlerinden Velopack ile güncelleniyor. Her paketin SHA-256'sı sürüm notlarında ve paket listesinde
  (ve GitHub'ın özetinde) aynı olmalı, yoksa kurulmuyor; güncelleme ancak TM Concept kapandıktan sonra uygulanıyor. Sonraki sürümden
  itibaren yalnız değişen kısmı taşıyan küçük bir *fark* paketi iniyor (0.1.25'in başlangıç alınacak paketi yoktu).
- Taşınabilir dosyaların adında artık sürüm yok; kendini güncelleyen kopyanın adı hep doğru kalıyor.
- Veritabanını başka bir kopya ya da öteki tür daha yeni bir sürüme yükselttiyse bu kopya ona dokunmuyor, kilit açma penceresinde
  **Bu kopyayı güncelle** diyor.

**0.1.25 ya da daha eskisinden geliyorsan**
- Programın her zamanki gibi kendini güncelliyor ve **taşınabilir** türü alıyor, eski dosya adıyla (örneğin `TMConcept-0.1.25-win-x64.exe`
  artık 0.1.26'yı açıyor). Bir sonraki güncelleme adını `TMConcept-Portable-win-x64.exe` yapıyor.
- İlk açılışta bir kez **"TM Concept kurulsun mu?"** diye soruyor: *Kur* aynı sürümün kurulum dosyasını aynı sürüm sayfasından indiriyor,
  SHA-256'sını denetliyor, çalıştırıyor ve taşınabilir kopyayı kapatıyor (o dosyayı sonra silebilirsin). *Taşınabilir kalsın* hatırlanıyor;
  Ayarlar → Genel → *Sürüm türü* bölümünde **TM Concept'i kur** sonra da duruyor. Hiçbir şeyi yeniden ayarlaman gerekmiyor: iki tür aynı veriyi
  kullanıyor.
- Ayarlar → Genel → *Sürüm türü* hangi türün çalıştığını ve sürümünü gösteriyor; kurulu türde **Kısayolları yeniden oluştur** var.

**Program güncellemeden yeni modeller**
- Yeni modeller (programın zaten tanıdığı çevrimiçi sağlayıcılar, sd-cpp için yerel görsel modeller, Ollama metin modelleri) artık bu
  projenin deposundaki bir katalog dosyasından gelebiliyor; arka planda günde en çok bir kez okunuyor. Böylece yalnız model ekleyen bir
  sürüm için programı güncellemek gerekmiyor. Kuralları sıkı: yalnız bu depodan, HTTPS ile; her dosya sabit bir Hugging Face commit'inde,
  SHA-256'sı ve boyutuyla; Ollama modelleri tam etiketi ve manifest özetiyle; yalnız programda zaten olan motorlar ve seçenekler. Bozuk
  dosya tek günlük satırıyla yok sayılıyor, açılışı hiç geciktirmiyor; yerleşik katalog hep duruyor. Dosya şimdilik boş.
- Daha yeni bir sürümün kurduğu görsel model klasörü Depolama'da ayrı satırda görünüyor, "Kullanılmayanları temizle" onu hiç almıyor.

**Henüz gerçek bir bilgisayarda denenmedi:** kurulum dosyasıyla kurmak, kurulu türün güncellemeleri (ilki 0.1.27 ile gelecek), 0.1.25'ten
taşınabilir türe güncelleme ve "TM Concept kurulsun mu?" geçişi yalnız otomatik testlerle denetlendi. Linux AppImage'ı üretiliyor ama
Linux'ta denenmedi; bu yüzden henüz önerilmiyor.
